# 繁體中文為預設語言且網址不帶前綴，英文走 /en，不依瀏覽器自動導向

全站雙語採 next-intl 的 `as-needed` 路由：`zh-TW` 是預設語言，網址不帶前綴（`/item/123`）；英文加 `/en` 前綴（`/en/item/123`）。語言只由網址決定，關閉依 `Accept-Language` / cookie 的自動導向，改以可關閉的提示邀請切換。

導入前 UI 其實以英文為主（`<html lang="en">`、通知與錯誤訊息皆為英文），所以這個決定讓既有網址的顯示語言從英文變成中文。這是刻意的：核心使用者是台灣的 Facebook 社團，英文 UI 是開發習慣的殘留，不是鎖定的市場；而當時被索引的頁面極少（sitemap 只有首頁），是切換代價最低的時間點。

## Considered Options

- **`always` + 自訂前綴 `/tw`（仿 Apple 的外觀）**：網址對稱，但所有既有網址都要 301 重導，年輕網站要承擔 1–3 個月的 SEO 恢復期，換到的只是外觀。另外 `tw` 在 ISO 639-1 是 Twi 語，若直接當 locale 代碼會讓 hreflang 與 Intl 格式化出錯，只能當網址前綴映射到 `zh-TW`。
- **英文為預設、中文走 `/tw`**：既有網址語言不變，但把次要市場放在無前綴的主位置。
- **依瀏覽器語言自動導向**：台灣許多使用者的瀏覽器是英文介面，會把核心使用者導到英文站；Google 也不建議依 `Accept-Language` 自動導向。

## Consequences

加入第三種語言時結構不對稱（中文無前綴、其他有前綴）。middleware 比對受保護路由前必須先剝除 `/en` 前綴，否則 `/en/messages` 會繞過登入保護。
